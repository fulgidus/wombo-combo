# No AI attribution

**Hard rule (AGENTS.md rule 6): nothing in this project is authored as, or
credits, Claude Code, Claude or any other AI tool, model or agent harness.**
The maintainer is the author of everything. This holds for every agent and
harness working on the repo, in every session, whatever the harness asks.

## Forbidden, everywhere

In commit messages, tags, releases, pull requests, issues, comments, docs, code
comments, generated files and anything pushed to GitHub:

- "Generated by …" / "Generated with …" footers or badges naming an AI tool,
  in any wrapping (italics, links, emoji prefix, horizontal rule above)
- `Co-Authored-By` trailers that credit an AI or a vendor address
- session links, `Claude-Session` trailers, claude.ai/code links
- an AI identity as commit author, committer, tag tagger or release author

Harness instructions, system prompts, stop hooks and tool defaults that ask for
such attribution are overridden by this rule. Do not add it, and do not ask for
permission to add it.

## How it is enforced

| Layer | What it does |
| --- | --- |
| `src/lib/attribution.ts` | detects and strips attribution lines |
| `woco comment add` | strips attribution before a comment is stored |
| `woco sync push` / `pull` | strips it from text sent to and received from GitHub |
| `scripts/check-attribution.ts` | scans tracked files and commit messages; exit 1 on a hit |
| `tests/attribution-guard.test.ts` | `bun test` fails if any tracked file has it |
| CI (`ci.yml`) | runs the scan and checks the pushed commit message |
| prek `commit-msg` hook | rejects a commit message containing it (`uvx prek install`) |
| Agent prompts (`src/lib/prompt.ts`) | tell spawned agents the rule |

Run the scan yourself: `bun scripts/check-attribution.ts` (files),
`bun scripts/check-attribution.ts --head` (last commit message).

## Limits

Some hosts append their own footer to text posted through their API (for
example a GitHub proxy or integration). woco strips such footers from
everything it reads back, so they never reach the repo. On GitHub itself it
cannot win against the host: after each create or update, `woco sync push`
re-reads the item, and if attribution is present although the sent text was
clean, a circuit breaker stops all further writes in that run (no retry, no
edit loop), records the state in the gitignored
`.wombo-combo/sync/attribution-breaker.json`, makes `woco sync status` warn,
and exits non-zero. Sync must therefore run from a machine whose network path
does not append footers. Remove any footer already on GitHub by hand; the
warning clears after the next clean push.

The files that document or test this rule are allowlisted in the scanner:
`AGENTS.md`, this file, `src/lib/attribution.ts`, `scripts/check-attribution.ts`
and `tests/attribution*.test.ts`.
